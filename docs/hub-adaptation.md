# 首批暴力区原样接入 Hub 与验收

## 已确认的边界

原游戏脚本零修改。Hub 从现有大厅 API 获取原 `content` 并直接执行，不注入生命周期代码、不改写执行环境、不向脚本传参，也不依赖原脚本返回卸载函数。

授权失效或新设备替换旧会话后，由 Hub 调用本地玩家的 `Kick()`，通过 Roblox 原生提示断开当前服务器会话。它不是逐资源卸载，不关闭整个 Roblox 进程，也不回滚已发生的服务器动作。

此前暴力区的侵入式 `hub.lua` 候选及专属测试已移出仓库并留存本机临时归档；原有 `Violence-District/loader.lua`、`ViolenceDistrict/loader.lua` 及其他已跟踪游戏文件保持原样。`hub-config.pending.json` 仅记录待验收游戏范围，不含新游戏正文，也未写入生产。

`hub-v1.1.0` 已完成 GitHub 发布及后端公共资源同步；当前国内、海外加载入口统一为 GitHub，不再分发国内备用入口。此次入口调整不部署新后端代码、不执行数据库迁移，不改原始游戏脚本或生产账号、会员数据。用户明确暂不启用暴力区，也不准备测试 Key；完整游戏加载验收留待配置启用后进行。实际发布和同步结果以 Release、资源校验和及运维记录为准。

首次绑定或切换游戏后保存会暂停 Hub，需核对后再启用；Game 创建或关联本身不启用脚本，也不发 Key。稳定游戏 ID 沿用现有单游戏权益标识，不改已有 Key。此实现需先应用后端新增 Game 迁移并发布后台，当前不执行生产迁移，暴力区保持未启用。

## Hub 的统一处理规则

| 场景 | 行为 |
| --- | --- |
| 初次 Key 校验失败 | 拒绝加载并提示，不断开游戏 |
| 已登录后 Key 到期、吊销、重置或会员失效 | 收到服务端确认后结束本局 |
| 新设备登录使旧会话失效 | 旧客户端下一次检查发现后结束本局 |
| 短暂网络错误 | 先重试；错误响应不续租，原租约耗尽仍未恢复则结束本局 |
| 收起、关闭界面或外部清理 Hub UI | 只释放/隐藏界面，不注销会话，后台授权监控持续运行 |
| 重新执行 Hub 加载入口 | 复用后台控制器并恢复界面，不重复登录、加载脚本、获取目录或创建监控 |
| 登录、下载、编译期间关闭界面 | 已发起操作可在后台完成，不视为取消 |
| 点击「结束本局」 | 明确断开当前游戏 |
| 原脚本开始执行后报错 | 只提示状态，继续后台授权监控；需重试时手动结束本局，避免叠加残留任务 |
| Kick 请求报错 | 停止 Hub 加载与续租，明确要求手动离开本局，不伪报游戏已断开 |

一局最多启动一份脚本；切换或重载先手动结束本局、重新进入游戏。关闭或清理界面不触发自动结束，避免 UI 重建误踢；后台控制器和会话单例保留，重新执行入口即可恢复界面，再点击「结束本局」。恢复显示最近状态，未提交输入和搜索重置；重建视图失败只告警，后台校验及原截止时间继续生效。

现有心跳约 30 秒，网络错误约 3 秒后重试，租约最长 90 秒且不超过权益到期。服务器立即使旧凭证失效，客户端通过后续检查发现，不是服务端实时推送弹窗。看门狗独立于 HTTP 心跳及界面，晚到成功响应不复活已终止会话；控制器真正终止后，晚到脚本和视图都不再启用，收到的晚到登录凭证尽力注销。

## 验证与发布顺序

1. 本地验证新 Hub：原文和零参数执行、无游戏清理契约、明确失效、顶号、断网耗尽、挂起和晚到响应、关闭/销毁/恢复视图、后台续租及手动结束路径，覆盖原始源码与真实混淆构建产物。
2. 通过 GitHub 统一发布新 Hub 版本；Key 页和旧链接兼容资源按需同步，API 地址保持不变。历史 `hub-v1.0.0` 仍是旧行为；新版本为 `hub-v1.1.0`，不提前开放脚本。旧版单例会提示重新进入游戏，而非复用旧策略。
3. 先在游戏管理创建或核对 Game 的原始链接、图片及识别范围，再读大厅 ID 63 的当前详情与 revision。只关联该 `gameId` 并保存待验收的 `hubConfig`，原正文、地址和大厅状态保留；绑定后复核，再按验收结论开启。并发编辑时先刷新。
4. 字段沿用原 API：`lifecycle=managed` 表示 Hub 会话终止策略及游戏接入已验收，`enabled=true` 开放目录；不再表示原脚本接入了 `context.onCleanup`。首批只开放 ID 63，不批量处理其余记录。
5. 临时暴力区 Key 与有效会员 Key 分别验证原脚本加载；第二设备登录、到期/吊销、断网耗尽及手动结束应显示原生断开提示，关闭或清理 UI 不应断开。测试授权结束后清理。
6. 若异常，仅关闭该条 Hub 开关并回退客户端版本，不删除账号或会员数据，不整库回滚；每批保留逐条验收和回退记录。

本轮保留 pending 配置，因此 Hub 目录尚未开放暴力区。正式开放前，先让新客户端的断开能力通过真实执行器的受控测试，再结合原脚本完成联调；不以本地替身测试代替真机结论。

## 已知边界

Kick 表示断开当前服务器，不表示所有执行器线程或本机进程已被销毁。该策略依赖客户端调度和原生方法；非让出式死循环、执行器 Hook、修改或使用旧公开客户端都可能影响执行，不是绝对防破解。已下发的代码也不支持远程回收。

仅删除 UI 不影响后台控制器；若执行器清理同时终止后台协程或重置运行环境，监控也会受影响。

本地回归使用模拟 Kick，真实执行器的 UI 清理/恢复、原版游戏脚本、外部依赖和原生弹窗仍待验收；原脚本保持原样，不增加脚本打包部署流程。

## 暴力区真机验收清单

### 当前前置状态

暴力区仍未启用，不发放本轮测试 Key，也不修改 ID 63 的正文或配置。**发布新版 Hub 不会自动让暴力区出现在目录中。** 完整验收开始前，再通过现有管理员 API 临时启用 ID 63 的 Hub 配置并准备专用测试 Key；临时启用会公开显示目录，应单独记录并在测试后按结论保留或关闭。

先在 Game 中统一填写 `id=violence-district`、官方游戏原始 URL、真实原始图片 URL、`universeIds=[6739698191]`、`placeIds=[93978595733734]`、`universal=false`。脚本只选择所属 `gameId`，保持原正文、脚本地址与大厅状态不变，使用最新 revision 保存关闭 / 待验收配置；绑定保存后复核，再按验收结论设置 `enabled=true`、`lifecycle=managed`。当前本地 pending 文件继续保持关闭，不直接把它当作启用配置。管理员 Key 页面是 <https://admin.zldelf.cloud/#/hub/keys>；已具备有效会员的测试账号也可从 <https://www.zldelf.cloud/api/hub/keys> 领取会员 Key。测试 Key 不提交仓库，不放进 URL，不发送截图明文。

### 启用后的执行步骤

每项会结束游戏的测试均使用新进入的一局，并确保本局内没有运行旧 Hub。游戏效果验证可能触发游戏自身规则或处罚，使用专用测试账号与允许的测试场景；不要用真实付费主账号试错。

1. **确认游戏与设备**：进入暴力区，执行 `print(game.GameId, game.PlaceId)`，记录设备、执行器及版本、两个 ID。ID 与上述配置不匹配时先记录确认，不把游戏范围扩成通用。
2. **错误 Key 不误踢**：加载 Hub，输入一个无效 Key 点击校验；应提示失败且游戏继续，不加载原脚本。没有建立有效会话时，重新打开界面后可再填正确测试 Key。
3. **正常登录与加载**：用正确测试 Key 校验，在 Hub 中搜索暴力区，加载 ID 63 对应的候选入口一次。核对原版中文菜单、实际常用功能及第三方依赖；原脚本保持原样，上游失效/网络报错应单独记录，不通过替换正文掩盖问题。重复点击不叠加脚本。
4. **关闭后后台运行**：点击「关闭界面」，观察至少 40 秒，游戏不因关闭 UI 断开，原脚本继续按其原逻辑运行。重新执行同一 Hub 加载入口，应恢复最近状态，不重复登录或再次启动游戏脚本。搜索及未提交输入重置属于预期。
5. **仅清理 Hub UI**：再执行下面的测试辅助代码，只删除 Hub 窗口，不动原脚本源码或其菜单。等待 40 秒后仍不应断开，再用同一加载入口恢复；可重复 3 次，避免使用会一起杀掉后台协程的“清空所有脚本”功能。

```lua
local playerGui = game:GetService("Players").LocalPlayer:WaitForChild("PlayerGui")
local hubGui = playerGui:FindFirstChild("RSZH_Hub")
if hubGui then hubGui:Destroy() end
```

6. **后台顶号确实生效**：在设备 A 登录并加载后关闭/清理 Hub UI；设备 B 进入同一游戏，使用同一 Key 登录。A 应在后续心跳检测后显示 Roblox 原生“其他实例或设备登录”提示并断开，通常约 30 秒；B 保持有效。仅“40 秒未断开”不充分，这一步用于证明 UI 不在时后台监控仍工作。
7. **吊销与到期**：在新的一局重复关闭 UI，再从管理后台吊销该专用测试 Key；下一次检查应显示失效原因并断开。自然到期/会员失效另用专用测试权益验证，不改现有真实会员到期数据来制造条件，也不把“吊销通过”当作“自然到期已验证”。
8. **网络边界**：短暂阻断授权 API 应先重试，及时恢复且未耗尽原租约时继续游戏；持续不可达则最晚在原租约耗尽后的本地检查时尝试断开，租约最长 90 秒。断开整个网络可能先触发 Roblox 自身掉线，该情况不作为 Hub 看门狗通过的依据；记录原生提示原因，优先用只针对授权 API 的受控网络测试。
9. **手动结束**：新的一局加载后关闭 UI，再恢复界面点击「结束本局」；应显示明确原生断开提示。重新进入游戏再加载，应是一份新会话。原脚本自身报错仅提示并继续授权监控，不自动踢人；如果已产生部分副作用，手动结束本局后重试。
